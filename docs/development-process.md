# 开发流程与执行步骤

## 1. 总原则

- **小步推进**：严格按阶段执行，一个阶段完成并验收后才进入下一阶段。
- **文档同步**：每个阶段结束必须更新 `devlog/DEVLOG.md` 与 `devlog/TODO.md`，并 git 提交。
- **验收驱动**：每阶段有明确的「完成标准」，达到标准才算完成。
- **稳定优先**：不追求一次性实现全部功能；出现未预期问题时先记录、再修复、再继续。

## 2. 阶段总览

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| 0 | 项目骨架与文档 | docs/devlog/AGENTS/README 齐全，首次提交完成 |
| 1 | Electron 应用骨架 | `npm start` 打开 900×680 粉色无边框窗口 |
| 2 | 静态 UI 与交互 | 无后端也能完成增删分段、校验、假进度演示 |
| 3 | qpdf 集成与 PDF 信息读取 | 普通/受限/加密 PDF 都能正确显示总页数 |
| 4 | 切分与输出 | 端到端切出正确无水印文件，含命名与进度 |
| 5 | 打磨与边界 | 边界场景、错误提示、窗口细节全部通过测试 |
| 6 | 打包与交付 | 便携 exe 在干净电脑可用，交付使用说明 |

## 3. 每个阶段的标准工作流

1. 阅读本文件与相关标准文档（技术/设计/测试）。
2. 实现本阶段全部待办（见 `devlog/TODO.md`）。
3. 按 `docs/testing-acceptance.md` 中该阶段的验证项自测。
4. 更新 `devlog/DEVLOG.md`（完成、问题、决策）与 `devlog/TODO.md`（勾选）。
5. git 提交：信息格式 `类型: 简述`（如 `feat: 初始化 Electron 窗口`）。
6. 向用户汇报本阶段结果，**等用户确认后再进入下一阶段**。

## 4. 阶段 1：Electron 应用骨架

目标：跑通最小可运行窗口。

任务：

- 初始化 `package.json`（type 为 commonjs；安装 electron 与 electron-builder 为 devDependencies）。
- `main.js`：创建 BrowserWindow，900×680，`frame:false`，`contextIsolation:true`、`nodeIntegration:false`、`sandbox:true`，加载 `renderer/index.html`。
- `preload.js`：contextBridge 暴露窗口最小化/关闭与文件选择等白名单方法（通道见技术方案）。
- 最小渲染页面：粉色背景 + 居中「粉色 PDF 分页器」占位文案，标题栏可拖动。
- 完成标准：`npm start` 正常打开窗口；标题栏拖动、最小化、关闭正常；无控制台报错。

## 5. 阶段 2：静态 UI 与交互

目标：界面完整可交互，但切分用假数据。

任务：

- 按 `docs/ui-design-spec.md` 实现标题栏、拖拽区、分段卡片、主按钮、结果卡片、密码弹窗的全部样式与动效。
- 实现分段增删（1–10 段）、输入校验（越界/起始>结束/空段）、假进度演示。
- 拖拽区支持拖入文件显示高亮（暂不真正读取）。
- 完成标准：所有组件与动效符合设计规范；校验逻辑与交互可用；无控制台报错。

## 6. 阶段 3：qpdf 集成与 PDF 信息读取

目标：程序能识别 PDF 并显示总页数。

任务：

- 下载 qpdf Windows 稳定版到 `vendor/qpdf/`，把版本号回填 `docs/technical-design.md`。
- 主进程封装 `runQpdf(args)`：spawn 异步执行、超时与错误处理。
- 实现 `pdf:inspect`：普通文件直接返回页数；受限文件直接处理；需密码时返回 `needPassword`，渲染层弹密码框，带密码重试。
- 完成标准：普通/受限/密码 PDF 均能正确显示总页数；密码错误提示友好。

## 7. 阶段 4：切分与输出

目标：完整切分流程可用。

任务：

- 实现 `pdf:split`：逐段调用 qpdf `--pages` 提取；每段发送进度事件。
- 输出目录：默认「原文件名_分页结果」；用户可通过 `dialog:choose-output` 自定义。
- 命名与重名处理按 `docs/technical-design.md` 第 6 节。
- 完成后返回文件列表，渲染层显示结果卡片与「打开输出文件夹」。
- 完成标准：多段、跳页、重叠、部分导出均正确；进度显示准确；输出文件可用 WPS/Adobe 打开。

## 8. 阶段 5：打磨与边界

任务：

- 边界：1 页 PDF、1–1 段、10 段上限、特殊字符文件名、输出目录被占用/无权限。
- 错误统一为中文友好提示（qpdf 失败、密码错误、文件被占用、输入非法）。
- 窗口细节：最小尺寸、拖拽命中区域、缩放时布局不破。
- 回归测试阶段 2–4 全部交互。

## 9. 阶段 6：打包与交付

任务：

- electron-builder 配置：应用名、图标（阶段 6 制作）、portable 目标、`extraResources` 含 qpdf。
- 在干净环境（无 Node/Python）双击验证 exe。
- 编写 `docs/使用说明.md`（一页纸：如何导入、如何填分段、如何找输出文件）。
- 更新 README 的快速开始与结构说明。

## 10. Git 规范

- 分支：`codex/` 前缀（如 `codex/dev`）；当前仓库无提交时先在 master 上完成阶段 0 首次提交，阶段 1 开始前切换/创建 `codex/dev`。
- 提交信息：`feat: xxx` / `fix: xxx` / `docs: xxx` / `chore: xxx`，中文简述。
- 一个阶段一次或多次提交，但禁止把未验收的半成品提交到主分支。
